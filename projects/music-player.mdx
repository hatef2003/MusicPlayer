# Android Music Player

*Production-quality Android music player with lyrics integration, audio metadata embedding, and a terminal-green hacker aesthetic.*

---

## Overview

This project is a fully-featured Android music player built from scratch in Java, designed for a polished user experience with deep lyrics integration and persistent audio metadata management.

The application supports:

- device music scanning via MediaStore
- track and album browsing with search and sorting
- foreground media playback service with notification controls
- online lyrics fetching from lrclib.net (synced LRC and plain text)
- lyrics caching for offline access
- lyrics embedding into audio file metadata (ID3 USLT / Vorbis LYRICS)
- speech-to-text lyrics fallback
- theme customization (System/Light/Dark + 4 accent colors)
- audio output routing (Bluetooth, Cast, speakers)

The architecture was designed for reliability, clean separation of concerns, and a distinctive terminal-inspired visual identity.

---

## Motivation

Most open-source Android music players lack:

- proper lyrics integration with caching and embedding
- modern Material Design theming with accent color customization
- clean architecture with separation between UI, service, and data layers
- scoped storage compatibility for metadata writing on Android 10+

The goal of this project was to build a music player that combines:

- a unique hacker terminal aesthetic
- real-world lyrics pipeline (fetch → cache → embed → display)
- robust playback architecture with foreground service and MediaSession
- production-quality code patterns (singleton manager, callback system, file-based caching)

## Architecture

The application follows a layered architecture with clear boundaries:

| Layer | Components | Responsibility |
|---|---|---|
| **UI Layer** | MainActivity, TracksFragment, AlbumsFragment, AlbumDetailActivity, NowPlayingActivity, SettingsActivity | User interaction, rendering, input handling |
| **Business Logic** | PlaybackManager, LyricsService, LyricsCache, LyricsEmbedder, SettingsManager, MusicRepository | Playback coordination, lyrics pipeline, settings persistence, data queries |
| **Service Layer** | MusicService | Foreground MediaPlayer service, notification, MediaSession |
| **Data Layer** | Song, Album models, MediaStore ContentProvider, lrclib.net API, file-based JSON cache | Data models, device music access, network lyrics, persistent cache |

### Playback Flow

```
UI (Activity/Fragment)
       ↕ PlaybackManager.Callback
PlaybackManager (singleton)
       ↕ ServiceConnection (bind)
MusicService (foreground Service)
       ↕
MediaPlayer + MediaSessionCompat
```

### Lyrics Pipeline

```
1. LyricsCache.get(artist, title)     → return if cached
2. lrclib.net API GET request         → synced LRC or plain text
3. MediaMetadataRetriever             → embedded metadata fallback
4. Error callback                     → speech-to-text available
```

After successful API fetch:
```
LyricsCache.put()         → persist to cacheDir/lyrics/*.json
LyricsEmbedder.embed()    → write USLT/LYRICS tag into audio file
```

## Key Features

### Music Discovery and Browsing

The application queries `MediaStore.Audio.Media.EXTERNAL_CONTENT_URI` to discover all music files on the device. Songs are grouped into albums using a `LinkedHashMap` keyed by `ALBUM_ID`, preserving insertion order.

The Tracks tab supports five sort modes:

- Title (alphabetical)
- Artist (alphabetical, then title)
- Album (alphabetical, then title)
- Duration (shortest first, then title)
- Date Added (newest first, then title)

Both tabs support real-time search filtering by title, artist, or album name.

---

### Foreground Playback Service

`MusicService` is a bound + started foreground service that wraps `MediaPlayer`:

- Manages a play queue with index tracking
- Auto-advances to the next song on completion
- Builds `MediaStyle` notification with previous/play-pause/next actions
- Loads album art asynchronously for notification and MediaSession metadata
- Handles notification actions via `PendingIntent` (PAUSE, RESUME, NEXT, PREV, STOP)
- Compatible with Android 14 foreground service type requirements

---

### Lyrics Integration

The lyrics system is the most technically complex feature, involving multiple subsystems:

**Fetching**: The app queries lrclib.net with artist and track name. The API returns both synced LRC format (with timestamps) and plain text. Synced lyrics are preferred.

**Parsing**: A custom LRC parser extracts timestamps in `[mm:ss.xx]` or `[mm:ss.xxx]` format, supporting multiple timestamps per line. Lines are sorted chronologically.

**Caching**: Lyrics are stored as JSON files in `cacheDir/lyrics/`, keyed by sanitized `artist_title.json`. Each file contains an array of `{ts, t}` objects. Corrupted cache files are auto-deleted on read failure.

**Embedding**: After successful API fetch, lyrics are written into the audio file's metadata using Jaudiotagger:
- MP3 files: ID3v2 USLT (Unsynchronised Lyrics/Text) tag
- FLAC files: Vorbis LYRICS tag
- Android 10+ scoped storage: copy to temp → modify → write back via ContentResolver

**Display**: Lyrics appear in a ScrollView with monospace terminal-green text. The album art shrinks from 240dp to 100dp when lyrics mode is active.

**Refresh**: A "🔄 Refresh" button forces re-fetch from the internet, bypassing cache.

---

### Theming System

The app implements a three-axis theming system:

**Theme Mode** (System/Light/Dark): Applied via `AppCompatDelegate.setDefaultNightMode()` in both `BaseActivity` and `MusicPlayerApplication` for consistent startup theming.

**Accent Color** (Green/Blue/Orange/Purple): Each color has a dedicated Material theme variant that overrides `colorSecondary`, `colorControlActivated`, and `colorControlHighlight`. Applied via `setTheme()` before `super.onCreate()`.

**Visual Identity**: The default theme uses a hacker terminal palette:
- Pure black background (`#000000`)
- Terminal green text (`#00FF41`)
- Dimmed green secondary text (`#00B32C`)
- Monospace font throughout all UI elements

---

### Audio Output Routing

A `MediaRouteButton` on the Now Playing screen is configured with `MediaRouteSelector` supporting `CATEGORY_LIVE_AUDIO` and `CATEGORY_LIVE_VIDEO`. This enables routing audio to Bluetooth headphones, external speakers, Chromecast devices, and other output targets.

## Challenges

### GridLayoutManager Layout Crashes

One persistent issue was `InflateException: You must supply a layout_width attribute` when inflating album card XML inside a `GridLayoutManager`. This occurred because the `RecyclerView` generates layout parameters for child views, and XML inflation with custom root attributes conflicted with the grid's layout parameter generation.

**Solution**: The `AlbumAdapter` was rewritten to build all views programmatically in Java, bypassing XML inflation entirely. This eliminated the crash completely.

### Scoped Storage Metadata Writing

On Android 10+, direct file path access to audio files is restricted. The `MediaStore.Audio.Media.DATA` column returns null for most files.

**Solution**: A dual-path approach was implemented:
1. Try direct file path first (works on API < 29 and some devices)
2. Fall back to scoped storage: copy audio to temp file → modify with Jaudiotagger → write back via `ContentResolver.openOutputStream(uri, "wt")`

### Lyrics Cache Consistency

Ensuring cached lyrics remain valid across app updates, device reboots, and cache clearing required careful file management.

**Solution**: File-based JSON cache with sanitized filenames, automatic corruption detection (delete on parse failure), and a manual refresh option for users to force re-fetch.
